# Decision trail

One entry per decision that shaped the work, newest at the bottom. Current state and next steps live in `PROGRESS.md`.

## 2026-09-11

- Project lives at `~/life-is-a-game`. Everything for the app stays inside this folder.
- Generic vocabulary only in code and templates. Path, Role, Node, Milestone, Cue, LogEntry. The owner's own paths (guitar, magic, lab, car) are test data under `testdata/`, never shipped as templates.
- Two node kinds, quest and practice. A decision is a Path role, not a node kind. Four independent critics cut the Decision node type as schema for one item.
- Milestones are sentences the user ticks. No numeric stage, no XP, no streaks. Research (Mekler 2017, Deci 1999) says counters hurt hobbies the user already loves.
- Surfacing engine is a pure Swift package (`Engine/`) with no UIKit or SwiftUI imports, so its tests run on Linux, no Mac needed. The app target depends on it. First full run on 2026-09-11: 20 tests, 0 failures. One test had drifted from the `record(_:in:)` signature (takes the whole paths array, as the app uses it) and was fixed.
- Storage in the app was going to be SwiftData. Revised the same day. The engine types are Codable already, so the app persists one `World` JSON document (paths, surfacing history, log) in Application Support with an atomic write. No SwiftData mirror classes, no mapping layer. Data is dozens of nodes for one user. SwiftData and CloudKit return only if phase 3 (sync, friends) ever happens. Laziness Protocol and Subtract Before You Add.
- Docker on this laptop hangs the CLI in a way `timeout` cannot kill. Not used anywhere in this project. Swift toolchain was going to come from mise, but mise's swift plugin 404s on Omarchy's OS id and deletes the install when the post-install check fails on missing libraries. Instead, the Ubuntu 24.04 tarball lives in `.toolchain/`, and `.toolchain/shim/` holds the two libraries Arch names differently (`libncurses.so.6` as a symlink to the system `libncursesw`, `libxml2.so.2` plus its `libicu74` dependency extracted from Ubuntu debs). `swift.sh` wires up `LD_LIBRARY_PATH`. User space, no root, no pacman.
- Today screen ships with a style switch (A one card, B objective plus paths, C paths first) behind Settings for the prototype weeks. The owner lives with each and one survives. Exhaust the Design Space, then delete the losers.
- Cues in phase 1 are time and date only (weekday, weekend, morning, evening, a date). Place and event cues wait for phase 2.
- Build pipeline is GitHub Actions macOS runners plus Splice on the Linux laptop. The workflow lives at `.github/workflows/build.yml`.
- Repo is public at github.com/nabil144/life-is-a-game (personal account, 2026-09-11). Public because GitHub bills macOS runners at 10x on private repos. The laptop keeps the work GitHub account (nabil-end) untouched: personal has its own SSH key (`id_ed25519_personal`), its own `github-personal` host alias, its own `gh` account entry, and the git identity is set per repo, not globally. `testdata/owner-paths.json` carries the owner's four example paths in the open, judged harmless (hobby names).
- First cloud build (2026-09-11) failed on 7 root causes, all in the app, none in the engine. The big one: SwiftUI exports its own `Path`, so the app declares `typealias Path = LifeEngine.Path` and never draws with SwiftUI's. `Notifier` needed `@Observable` to travel through `.environment`. `Objective` needed a public init. Settings body was too big for the type checker and became five small views. Second build was green across all three jobs; the Simulator screenshot shows onboarding. Artifacts land in `artifacts/`, gitignored.
- Three Today-screen mockups in `design/` as static HTML so the owner reacts to something on the phone before any SwiftUI exists.

## 2026-09-12

- `splice login` on the Linux laptop fails twice over. First, Arch's CA bundle lacks Apple Root CA, which `gsa.apple.com` chains to. Fixed with `~/.config/splice/ca/AppleRootCA.pem` and a `splice()` wrapper in `~/.bashrc` that sets `SSL_CERT_DIR`. Second, Apple's GrandSlam login POST answers with an HTTP 503 page, splice parses it as a plist, gets null, and segfaults (`coredumpctl list splice`). That is a splice bug plus an Apple-side rejection of the emulated anisette data, and nothing on the laptop is left to configure.
- First install moves to Xcode on the Mac. Splice on macOS would run the same login code against the same account, so the 503 may follow. Xcode signs in through Apple's own auth stack and handles device registration, Developer Mode, and the trust dialog. Cost: a free Apple ID signs for 7 days, so refreshes need the Mac again until the Linux pipeline works. Experience First. The point of the prototype weeks is living with the Today screen, not the pipeline.
- `PROGRESS.md` added as the first file to read in a session. It holds what the app is, status, and the session log. This file keeps the why. The workflow no longer runs on markdown-only pushes, so progress commits stop burning macOS runner minutes.
- First real use, same day. The owner made one Path from Xcode's build and found the New path form heavy. It asked for a name, an identity, a kind, a glyph, milestones, and quests, each its own field. Finding, not opinion. This is what the prototype weeks are for.
- Form trim first. New path now requires a name and one milestone. Identity defaults to the name, kind to hobby, glyph follows the kind, quests are optional and can be added from the path. Everything else sits under one collapsed "More" row. Templates stay as a one-tap menu. Subtract Before You Add: the chat below has less to fill because of this.
- Paths can be created by talking, behind a Settings toggle, default off. The model is Apple's on-device Foundation Models framework (iOS 26, iPhone 15 Pro and later, Apple Intelligence on). No cloud, no API key, no cost, nothing leaves the phone. The owner's phone is a 15 Pro. The model's job is to ask one short question at a time and write down what the person said, in their words. It never praises, cheers, or motivates, so the spec's "in the user's own words" and "no gamification" rules hold. The manual form stays beside it; the chat has a "Type it instead" exit. If the model is unavailable the toggle is replaced by a one-line reason and the form is used. This amends the phase 1 non-goal "No AI inside the app" to "No cloud AI".
- Deployment target moves from iOS 18 to iOS 26. Foundation Models needs 26, the only device this ships to runs 26.6, and one target beats availability guards in every view that touches the model. Laziness Protocol.
- Chat mechanics. One `LanguageModelSession` per sheet, so the transcript carries the conversation. Each turn asks the model for one `@Generable` value holding the whole path so far plus the next question. The schema goes in the prompt once (first turn), later turns skip it to save the 4k on-device context. The preview card is the live `PathDraft`, every line a text field, so editing needs no extra state. When the person edits by hand, the next prompt carries the edited path so the model builds on it. Both the chat and the form save through the same `PathDraft.begun(on:)` path into `Store.add`. No streaming in the prototype; the card updates per turn.

- The first Path "vanished" after the second Xcode install. Not a data bug. The owner had changed the bundle id to `com.nabil.LifeIsAGame` by hand in Xcode when signing; `LifeIsAGame.xcodeproj` is gitignored and regenerated, so `xcodegen generate` put `com.mystery.LifeIsAGame` back and Xcode installed a second app with an empty store. The first app, and the Path, are still on the phone. The storage model did not change between the two builds (`git diff 57b3d41..HEAD -- Engine/Sources App/Sources/Store.swift` is one `Equatable` conformance). Fix: `project.yml` now says `com.nabil.LifeIsAGame`, and the background task id and CI launch id follow it.
- Storage rule from the same scare. `Store.load` never overwrites a file it cannot decode. It moves the file to `world.broken-<unix time>.json` and starts empty, so the next save cannot destroy the data and the file is there to recover by hand. Decoding tolerance for old shapes was not added because no shape changed; that ships when a shape does.
- Chat discoverability. The toggle in Settings was the only way in, and the owner did not find it. The New path form now has a "Talk it through instead" row when the model is ready, a one-line reason when Apple Intelligence is off or the model is still downloading, and nothing on hardware that can never run it. The Settings toggle stays and now means "which one opens first". `Talk.State` (`ready`, `off`, `never`) is one enum both screens switch on.
- Quests and practices are editable on the path. They never were; Capture only added. Tap a node to change its words, kind, cue, or blocker. Swipe to let it go, which is the existing `letGo` action, so the node becomes "path not taken" and stays in history rather than being deleted. `CueEditor` is one view used by Capture and the editor.

- Reversal, same evening. Paths by talking moves off Apple's on-device model to a cloud model with the owner's own API key. Owner preference, stated plainly, and it holds up: it works on any iPhone, has no Apple Intelligence dependency (no eligible-device check, no model download, no "not ready" state), and the model can be swapped by typing a name. Cost is per-Path cents billed to a key the owner manages, plus the words leave the phone for the provider. Two providers to start, OpenAI (`POST /v1/responses`, `text.format` JSON schema, strict) and Anthropic (`POST /v1/messages`, `output_config.format` JSON schema, `anthropic-version: 2023-06-01`). Defaults `gpt-5.6-terra` and `claude-haiku-4-5`, both editable, verified against the providers' docs on 2026-09-12. The `Turn`/`Sketch` contract is unchanged, decoded with `Codable` from one JSON schema both providers accept (closed objects, everything required, no count constraints since Anthropic strips them). `PathModel` is a protocol so a provider or a fake slots in; `Provider` is one enum holding endpoint, headers, request body, and envelope parsing. The transcript now lives in the view as `[ChatMessage]`, the assistant's turns echoed as the JSON it returned, so the model sees its own draft. Keys sit in the keychain (`kSecClassGenericPassword`, one item per provider) and nowhere else; provider and model name in UserDefaults. Setup appears once as a sheet after onboarding when no key is saved, with Later, and lives in Settings under New paths. Saving a key also turns on "Start new paths by talking", since that is why one saves a key. Errors map to five sentences (offline, bad key, busy, refused with the provider's message, unreadable) and never drop the draft. iOS 26 target stays; nothing gained by lowering it. `Talk.State` lost its `never` case; with a cloud model there is no hardware that can never do this.

- Today is the daily list of due quests and practices, not a second path browser. Owner lived with the one-card-plus-paths prototype and said the job is: open the app, see what to do, mark it done, it leaves. A practice returns when its cue allows (weekend, evening, a date); the seven-day notification cooldown does not hide it from Today. `Planner.due` is that list. Notifications still pick one. The A/B/C Today styles are retired.

- Practice frequency is the same cue, not a second type. Everyday, weekdays, weekends, every 3 days, weekly. That is `days` plus `every` (default 1 so old worlds stay everyday). Quests still ask when. World always draws twigs from each path to its open nodes; pinch still shows milestones.

- The words live in the app. Owner asked for a cheat sheet so they do not have to ask the agent what a milestone is. Schema unchanged; the fight was interpretation. The sheet uses their guitar-solo reading: a milestone is something you achieve and tick when you reach it. Settings, New path footer, and a question mark on New path. One screen, no tutorial on launch.

- Ticking a milestone is a fact, not a toggle. Owner unticked one by accident, reticked, and the day became today. First tap still marks it true today. A second tap opens The fact: change the day (the app may have arrived late) or take the tick back, which asks once more. Copy is "It was not true yet", not "you are falling behind". The log's day follows the fact; a taken-back tick drops that log row. `tickMilestone` no longer clears.

- Palette is Blood and brass. Owner picked it from three live mocks after rejecting paper (Leaf) and purple (Void), then rejecting those replacements' predecessors. Tokens: ground `#140C0E`, card `#231418`, words `#F0E4D4`, brass `#C9A15B`, wine `#8B2E3A`. Dark only. Brass is accent, ticks, and You. Wine is the World branches. No second light theme until someone asks. `Ink` is the one type; UIKit appearance paints lists, nav, and the tab bar so Forms are not still iOS grey.

- A World view of Paths, inspired by skill trees (Assassin's Creed, God of War, Path of Exile) but without unlocks, points, or locked nodes. You sit in the middle. Each Path is an orb on a bent branch. Pinch closer and milestones appear as small rings around that Path, ticked ones filled. Tap an orb to open the existing Path detail; authoring stays a text field, so the spec's "no canvas editor" holds. The list stays behind a World / List segment, same prototype-weeks pattern as the Today styles. Default is World so the new thing is seen. No new storage shape.

- The path itself was read-only after creation. Quests had an editor; name, identity, kind, glyph, deadline, and milestone wording did not. Owner asked once persistence landed. One sheet, This path, opened from the header or Edit. Milestone ticks stay on the detail screen so editing words cannot steal the tick gesture. `Store.update` already persisted the whole Path, including the Files copy. No new storage shape.

- Progress must survive a new version. The owner said recreating paths on each Xcode install would make the app unused. Application Support already survives Cmd+R when the bundle id stays `com.nabil.LifeIsAGame`. It does not survive deleting the app, a bundle-id change (already happened once), or a failed decode. iCloud Documents / CloudKit need a paid Apple Developer account; the owner is on a free Apple ID. So the copy lives in a Files folder they pick once (iCloud Drive is safest). A security-scoped bookmark remembers the folder for this install; every save writes `world.json` there. After a reinstall the bookmark is gone, they pick the same folder, and `keepACopy` restores. Settings also has Save a copy now (full world, ticks and log included) and Restore from a file (world or a PathBundle of drafts). Onboarding and the empty Paths list offer restore. A one-time sheet asks them to pick a folder once they have paths. This is not app-run sync; it is their folder.
